# Salt-ASMR 开发路线与验收

> 更新：2026-11-17。源码研究已完成一轮；以下均为开发目标，不代表宿主实测通过。API 证据见 [技术评审记录](TECHNICAL_REVIEW.md)。

## P0：先验证播放闭环

先制作最小探针插件，使用配置或快捷键触发，无需先建作品库 UI、完整数据库或播放状态机。

### 0. 锁定验证环境

- 记录宿主完整版本与分发渠道、Windows 版本、API 版本、JDK、Kotlin、Compose 和构建依赖。
- 以已发布的 `0.1.0-dev23` 为研究基线；核对实际依赖 jar 的方法表，不能用默认分支配置中的 dev22 代表最新 Release。
- API / Kotlin / Compose 等宿主提供的依赖使用 `compileOnly`；工具链与目标宿主匹配，不凭版本号假定兼容。

### 1. 官方事件探针

记录事件接收时间、状态、位置、当前媒体项及请求编号。覆盖分页曲库读取、权限拒绝、启用后已有歌曲、快速切歌和重载歌词。

需要回答：

- Ended 在每轨结束还是仅特定终止情形出现？是否与自动切轨竞争？
- 当前媒体项查询完成时，是否已切换到另一轨？
- 歌词缓存、预取和重载是否影响回调？不得将其视为切轨通知。
- 未入库文件播放时，官方查询能否返回足够的音轨身份？

### 2. 指定起播与完整队列（核心阻塞）

先核对实际 API；若仍无正式入口，研究第三方已存在的内部控制器调用。优先一次提交完整队列，由宿主执行连播，避免默认采用“收到结束后注入下一轨”。

已入库与未入库文件分别测试。M3U8 / 命令行作为备选探针，验证前不承诺其支持顺序、起始索引、单实例投递或队列替换。

| 验收项 | 通过标准 |
|---|---|
| 装载、反复启停、权限拒绝 | 不产生重复注册、遗留任务或普通播放异常 |
| 指定音轨 | 实际播放身份与目标一致；文件缺失明确失败；旧请求不会覆盖新请求 |
| 完整队列 | 队列内容、顺序与起始轨可确认；不能将退回单曲报告为整单成功 |
| 自动连续播放 | 不漏轨、不重复、不双跳，不依赖手动 next 掩盖问题 |
| 上一轨 / 下一轨 | 宿主按钮及媒体键按已定义的作品顺序工作，覆盖首轨和末轨 |
| 随机 / 循环模式 | 明确作品播放策略；若需内部模式控制，计入依赖和兼容成本 |
| 外部切歌、快速连续请求 | 放弃过期恢复请求，不向其他歌曲 seek，不强行抢回播放 |
| 同轨恢复 | 正确装载目标轨后 seek 一次，验证位置回执，不能以固定延迟代替就绪确认 |
| 停用、不兼容、撤销 Hook 权限 | 不继续提交失效请求；清理注册与任务，Salt 可继续普通播放，数据保留 |

### 3. 进度、字幕与窗口探针

- 进度采用串行处理、请求 / 生命周期代次及身份确认；位置回调与当前歌曲查询不是原子快照。
- 正常关闭恢复目标：同一作品版本、同一轨，位置误差不超过 2 秒；这是验收目标而非 API 保证。
- 异常退出允许有限数据损失，目标不超过最近约 10 秒；实测并记录实际边界。
- 验证 LRC / SPL 的日文、中文、双语、无歌词、长静默、超过 60 / 100 分钟、编码差异及跳转。语言切换后的主动歌词重载不是已确认的公开能力。
- 最小独立窗口验证关闭不退出宿主、重复打开、停用释放及 ClassLoader / Compose 兼容；暂不接管主导航。

### 样本与结果记录

先用 3 部 RJ，覆盖嵌套目录、原版 / 翻译版或音效分支、重复文件名、FLAC / MP3 / WAV、缺字幕和真实长音频。

每部作品累计覆盖至少 20 次自动 / 手动切轨；保存版本、样本清单、调用路径、日志、结果和未通过项。音轨身份错配零容忍。源码存在调用、静态自检通过、命令被接受与实际起播分别记录，不互相替代。

### 决策门槛

- **通过**：核心播放、队列、身份、恢复及失败回退均通过，内部依赖范围可解释、可回归，才进入 P1。
- **部分通过**：例如只支持已入库文件，明确限制并重新评估可接受范围，不悄悄扩大曲库导入要求。
- **不通过**：错轨、双跳、seek 竞态无法解决，或核心需要多处不稳定内部状态写入，暂停完整 UI 与产品扩展。
- 不用“混淆名少于 3 个”等数量规则代替可靠性判断；关注目标稳定性、行为语义、可检测性、影响面和维护工作量。

伴侣模式（作品浏览、字幕、近似进度提示）仅为可选择的降级产品。若不能满足核心需求，重新评估公开控制协议的成熟播放器；不立即恢复 Kura 全部范围。

## P1：小规模可日用版本（P0 通过后）

- 用户指定少量目录，识别 RJ、允许人工修正，保留版本 / 分支选择。
- 嵌套目录排序、自然排序与人工顺序覆盖；不把所有编码和音效版本串成一条队列。
- 最小作品列表 / 详情、逐轨起播、完整队列、作品版本级续播。
- 本地 LRC / SPL 匹配，原生歌词展示；字幕语言选择以已验证行为为限。
- 中文界面；不重新开发解码、输出与设备管理。
- 本地 SQLite 保存目录、身份、顺序与进度；有取消扫描、断盘保护、事务、迁移备份和导出。

## P2：收听体验

- 历史、已听完状态、收藏、基础搜索、时间书签。
- 当前续播位置与完成状态分开；误触和回听不覆盖唯一恢复点。
- 字幕匹配候选与人工确认，后续按真实样本引入 SRT / VTT 等外部 ASR 格式转换。
- 社团、CV、标签与自定义排序；不以在线抓取作为启动依赖。
- 文件移动恢复：多证据匹配，存在歧义不自动迁移进度。

## P3：大库优化

- 增量扫描与完整对账、扫描恢复、分页 / 虚拟列表、封面缩略图缓存。
- Salt 分页 API 不是增量变更流，跨页不保证一致快照，不能据此直接判断删除。
- 重复作品和重复文件分别处理；局部哈希不保证唯一，不自动删除原文件。
- 中日文实际查询样本与检索方案验证，按需求引入 FTS。
- 逐级扩大数据量，记录扫描速度、内存、响应与恢复正确性；不预判 Salt 对 10TB 曲库必然成功或失败。

## 架构与数据边界

单个 Kotlin 插件工程，先按包划分，不提前拆分多个 Gradle 模块、独立进程或服务：

```text
plugin/
  SaltAsmrPlugin
  host/
    SaltPlaybackAdapter       # 官方查询、事件、歌词与基础控制
    InternalPlaybackAdapter   # 版本受限的内部播放调用；反射与 Hook 分开
  catalog/                    # 识别、版本、排序、文件位置
  listening/                  # 身份关联、进度与恢复；P0 后确定状态机
  lyrics/                     # 匹配与格式适配
  store/                      # SQLite、迁移、备份和导出
  ui/                         # P0 后确定窗口形态
```

- 作品、版本、音轨使用自有稳定 ID；RJ 为外部编号，Salt ID 为可重建映射。
- 路径、大小、时长和按需局部哈希作为候选证据；不承诺百分之百自动恢复。
- 元数据、人工修正与可重建缓存分开；取消 / 失败扫描不能清除未见条目。
- 数据放本机应用数据目录并独立于插件安装目录，备份 / 导出位置可见；删除插件的数据策略需显式定义。
- 不每秒写库；合并更新，定期和暂停等事件落盘，异常退出不依赖 stop()。
- 内部播放和 UI 注入分别探测与禁用。未知宿主版本默认禁用内部控制，不以签名存在替代行为回归。
- Hook 自动注销不能撤销已发生的队列替换等副作用；不写 Salt 私有数据库、不替换宿主二进制。
- 复用 Kura 的样本、规则与经验；现有 TypeScript / Electron / mpv 实现不直接当作 Kotlin 模块搬入。

## 上游与发布

- 向上游提出最小能力需求：完整队列与起始轨、路径或媒体项起播、带身份的播放快照 / 事件、歌词重载。此处是提案，不是现有 API。
- 每次宿主升级重跑 P0 回归，记录明确支持的组合；不承诺整个 1.19.x 自动兼容。
- 第三方实现逐文件核对许可证，保留必要声明；发布前确定本项目许可证。
