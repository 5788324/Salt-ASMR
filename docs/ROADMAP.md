# Salt-ASMR 开发路线

> 更新：2026-11-17。产品范围已收缩为“插件自己的作品收藏与作品歌单”。

## 当前交付：0.1.0-alpha.1

已实现并在 Linux / JDK 25 上验证：

- Kotlin 单工程，官方 Workshop Gradle 插件打包 `.spmod`。
- JDK Swing 独立中文窗口，插件配置按钮入口，不依赖 Compose UI Hook。
- 只读导入 RJ 目录、自然排序、作品和音轨列表、基本搜索。
- 作品收藏；作品歌单增删改名、去重、移出与顺序调整。
- 自有 UUID 与 SQLite 存储，目录暂时缺失不删除收藏和歌单。
- 事务、独占写锁、损坏 / 高版本数据库拒绝覆盖、一致备份。
- 核心数据测试、真实 AWT 窗口交互测试、插件结构检查。

尚未完成：Windows Salt 内安装、配置入口、启停与 SQLite 原生库装载实测。详见 [验收清单](USAGE.md#windows-salt-验收)。alpha 不等于宿主兼容验收已通过。

## 下一步：Windows 宿主验收

先验证安装和启停、从配置按钮打开窗口、MP3 / WAV 文件夹导入、收藏 / 歌单保存、重启恢复、备份与还原。每次宿主更新记录完整版本并回归。

当前不申请曲库或 Hook 权限，因为本版不查询、修改 Salt 曲库或播放队列。收藏与歌单只存插件自己的数据。

## 后续 1：专辑 Tag 整理与字幕

允许修改 Tag 是用户已接受的产品方向，但本版尚未写入任何音频。先在副本上验证：

- 预览作品版本、音轨顺序与标签变化，只修改确认过的字段。
- MP3 优先，WAV 单独验证容器与 Salt 读取兼容性；未知结构拒绝写入。
- 不重新编码；音频主体与关键格式数据校验、完整备份、可恢复的文件替换。
- 避免原版 / 翻译版、MP3 / WAV、不同音效版本重复混入一个播放序列。
- Salt 重新扫描后，确认同一 RJ 能以原生专辑展示和顺序播放。
- LRC 优先原生读取，VTT 保留原文件并转换为 LRC / SPL 提供给宿主。

写 Tag 不等于获得官方队列控制。原生专辑归组必须实测，不能提前承诺。

## 后续 2：作品管理完善

- 封面、作品标题人工修正、版本 / 分支选择。
- 明确的移动目录重新关联，保留自有身份；多个候选必须人工确认。
- 进度与时间书签、历史；当前位置与完成状态分开。
- 中日文检索体验、大库增量索引和缓存，按实际数据逐级扩大规模。

RJ 为外部编号，路径和局部哈希仅用于匹配。扫描取消、权限失败与断盘不视为删除。当前为追加式重新扫描，已知但未再次发现的音轨保留，暂不自动清理。

## 后续 3：播放控制 P0（独立立项，当前不承诺）

研究基线及源码见 [TECHNICAL_REVIEW.md](TECHNICAL_REVIEW.md)。dev23 仍没有任意文件起播或队列读写接口；next / previous 不能定义 RJ 队列。

在实现作品歌单一键播放前，必须验证：

1. 已入库与未入库文件分别测试，不能预设曲库是必需条件或非必需条件。
2. 完整本地队列、任意起始轨、自动连播、宿主上一 / 下一轨、随机和循环模式。
3. 当前音轨与位置关联，外部切歌、快速请求和关闭插件时不串轨、不双跳、不错误 seek。
4. 重启恢复到同一版本、同一音轨；就绪后执行 seek，不依赖固定延迟。
5. 内部适配失效时停止提交命令，数据与普通播放保留。

内部反射与 Hook 分开描述，集中封装为可关闭、版本受限的 InternalPlaybackAdapter。未知版本默认禁用，静态方法匹配不替代行为回归。M3U8 / 命令行仅为待验证备选。

若这些条件不能在可维护的边界内通过，不扩展自定义播放控制。插件作品收藏与歌单可独立使用，但不应被描述为完整专辑播放器。

## 架构边界

单个 Kotlin 工程，按包划分：

```text
SaltAsmrPlugin             生命周期、配置入口
catalog/                   作品身份、只读扫描和排序
store/                     SQLite、事务、备份
ui/                        独立窗口与后台任务
```

后续确有需求再增加标签、字幕与宿主播放适配。无第二音频引擎、无独立服务、无企业级框架。不复制 Kura 的 Electron / TypeScript / mpv 架构；只复用经过核查的需求规则与样本。
